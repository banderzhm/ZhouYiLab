盲派八字分析规范 v1.0
======================

本文是 ZhouYiLab 的盲派分析规则规格，不是某一位师承的口诀汇编。
盲派不同传承在体用范围、做功效率、墓库和神煞上存在差异；本实现采用
“理法—象法—技法”三层框架，以“宾主—体用—做功”为主线，所有差异
通过 rule_set 版本和可选规则开关表达，不把一家口径伪装成唯一标准。

资料参考（仅作概念依据，具体实现以本文规则为准）：
- https://www.yuceju.com/ask/3198/
- https://zh.wikipedia.org/wiki/盲派命理
- https://asklingxi.com/zh-tw/books/duanjianye-mangpai-gaoji/02-he-xin-zuo-gong/05-jie

理论篇：盲派究竟如何看命
========================

一、根本问题不是“日主强弱”，而是“命局在做什么”
------------------------------------------------

盲派把四柱看成一幅已经发生作用的关系图，而不是五行数量统计表。每个字都
代表某类人、事、资源或环境；合、冲、刑、穿、克、生、墓表示这些对象正在
发生的行动。看局时依次追问：

```text
谁是我？        —— 主位与体
谁是别人？      —— 宾位与目标
我用什么去做？  —— 体神和做功工具
我在做什么？    —— 制、合、化、生、墓等作用
做成了什么？    —— 财、官、名、技、婚姻、迁动等结果
做功是否有效？  —— 力量、位置、清纯度和岁运引动
```

所以，财星出现不等于得到钱，官星出现不等于当官；必须看它是否进入主位、
是否被主位作用、作用链是否完成，以及在什么岁运被引动。

二、理法、象法、技法三层不可互相替代
--------------------------------------

理法回答“为什么”：食神制杀是以技术、表达或专业能力处理压力和规则；杀印
相生是借助平台、权力或贵人获得职位；比劫夺财是资源被竞争者分走或收入难以
落袋；食伤生财是把技能和输出转成收入；墓库收用是把分散资源收藏、管理和
控制。

象法回答“表现成什么”：

```text
人事之象 = 十神类别 + 所在宫位 + 干支物象 + 做功方式 + 触发时间
```

例如日支为夫妻宫，被宾位劫财合入比劫局，不应只写“有合”，而应解释为夫妻
宫被外部竞争、朋友或利益关系牵动，再结合冲、刑和岁运判断是合作、争夺还是
关系破裂。

技法回答“何时应”：墓库开闭、填实空亡、伏吟反吟、岁运并临、流月流日取应，
以及具体传承的口诀。技法必须建立在理法和象法成立之后，不能用单条口诀推翻
完整作用链。

三、盲派看局的六个理论层次
--------------------------

### 3.1 定主位和宾位

日干是命主立极点，日支是身体、家庭和夫妻宫，也是最重要的主位。禄、根及
与日主紧密相连的字，是命主拥有的本钱。年、月、时中与日主相对的字先作宾位，
代表外部人物、组织、资源和环境。宾位主动合、冲、克入主位，表示外部力量
进入我的生活；主位主动制、合、取宾位，表示我在获取或控制外部对象。

### 3.2 分固定宫位和动态宾主

年柱主祖上、早年和外部环境；月柱主父母、同辈、平台和工作环境；日柱主身体、
夫妻和当前自我；时柱主子女、成果、晚景和未来兑现。这些是主题，不是断语。
若时柱与日主形成强关联，可以提升为主位，但必须说明原因。

### 3.3 分体、辅助体和目标用

体是命主可调用的本钱，常见为日主、禄、根、印、比劫和食神；目标用是命主
希望取得、控制或改变的对象，常见为财、官、杀、伤官。盲派的“用”不等于
子平法的“用神”。同一个字可以在不同链条中改变角色：食神既可作技术工具，
也可作制杀之源；伤官既可作输出，也可成为破坏官星的风险；印既是平台，也
可能生旺比劫而使财星受损。

### 3.4 找主做功路径

先找最清晰、力量最大、结果最明确的一条主线，再看辅助线和破坏线：

```text
制用：体制财、官、杀等目标；
合用：主位与目标建立关系，区分合得、合住、合绊、被合走；
化用：杀印相生、伤官配印等借中介完成转化；
生用：食伤生财、财生官等形成资源链；
墓用：主位墓库收藏或控制宾位之物；
反向做功：宾位之体或用反过来作用主位。
```

“有关系”不等于“有效做功”，必须验证透藏、根气、距离、方向、合冲竞见、
空亡和墓库开闭。

### 3.5 判断功神、废神和层次

功神是参与有效做功且产生可解释结果的字或组合；废神是消耗力量但没有形成
有效结果的字或组合。层次不能由“关系数量”或固定总分直接决定，而应综合：

```text
做功强度、做功有效性、主导路径清纯度、最终结果、破坏链和救应链。
```

### 3.6 由结构取象并落到应期

比劫夺财可落为收入受阻、分成争议或支出失控；食伤生财可落为技术、产品、
外包或销售；食神制杀可落为凭专业解决规则和压力；日支被冲可落为婚姻、居所、
身体或家庭结构变化。原局定可能，大运定主题，流年定触发，流月和流日定窗口。

四、理论分析的标准顺序
----------------------

```text
1. 复核出生时间和四柱；
2. 以日干、日支定主位，列固定宫位；
3. 识别宾位及进入主位的方式；
4. 列出透干、藏干、本气、中气、余气和十神；
5. 分体、辅助体、目标用和风险源；
6. 明确“谁对谁做什么”，建立主做功路径；
7. 判断做功是否完成、效率高低和是否清纯；
8. 检查墓库、空亡、半合、拱局、刑冲穿害和特殊组合；
9. 把结构翻译成宫位和十神人事；
10. 用大运、流年、流月、流日验证应期；
11. 输出主象、次象、风险、救应和证据链；
12. 对传承不一致的内容标记待复核。
```

实现篇：规则与工程契约
======================

一、范围与术语边界
------------------

1. 盲派“用”不是子平法“用神”。
   - 体：命主拥有的本钱、工具和主位资源。
   - 用：命主希望取得、控制或改变的目标对象。
   - 功：体、用、宾、主之间产生有效结果的作用过程。
   - 功神：参与有效做功且产生结果的字或组合。
   - 废神：消耗力量但未形成有效结果的字或组合。

2. 本模块不重新排盘。年柱、月柱、日柱、时柱、藏干、十神、大运、起运、
   旬空、节气、命宫、身宫等由 BaZiBase/GanZhi 基础模块提供；盲派模块只
   消费这些结果。顺逆和起运规则不得在盲派分析器中重复实现。

3. 旺衰只作背景证据，不作为唯一层次判据。子平和盲派结果必须分开保存，
   不能用盲派“用”覆盖子平“用神”。

二、输入与公共输出契约
----------------------

```text
BlindAnalysisRequest {
    BaZiResult chart;
    BirthContext birth_context;
    AnalysisConfig config;
    string rule_set = "mangpai-v1";
    optional<AnalysisQuestion> question;
}

BlindAnalysisResult {
    schema_version;
    rule_set;
    input_pillars;
    birth_context;
    occurrences;
    palace_assignments;       // 年、月、日、时宫位及主宾角色
    body_use;
    relations;
    work_chains;
    useful_waste;
    structures;
    timing;
    symbols;
    event_impacts;
    warnings;
    evidence;
}
```

当前 C++ 公共契约将上述内容映射为 `BlindAnalysisDetail`：
`palaces` 保存四宫主宾角色，`work_chains` 额外保存来源/目标柱位及双方十神，
`tombs` 保存墓库柱位、冲刑合穿关系、开闭状态和判定依据，`transit_impacts`
保存大运及流年对原局的引动摘要。中文报告和 JSON 输出必须同时呈现这些字段，
不得只保留不可追溯的自然语言结论。

盲派岁运使用独立的 `MangPaiTransitAnalysis` 契约，不复用子平
`TransitAnalysis` 的强弱、用神、喜忌和量化评分字段：

```text
MangPaiTransitAnalysis {
    fortune;       // 大运干支
    year;          // 流年干支
    triggers;      // 岁运引动：合、冲、刑、害、填实、伏吟等
    palaces;       // 宾主变化及四宫取象
    work_changes;  // 原局做功链被加强、牵绊或改道
    symbols;       // 干支、十神、宫位取象
    event_types;   // 财务、事业、关系、身体、迁动等应事类型
}
```

岁运中文输出固定按“岁运引动—宾主变化—做功链变化—宫位取象—应事类型”
五段呈现；子平模式仍单独输出强弱分数和喜忌，不得在盲派模式混入。

每条结论必须能回溯到具体干支、位置、十神、关系、有效力量和触发时间；禁止
只返回“富贵双全”“平常人”等没有证据链的结论。

三、基础资料标准化
------------------

### 3.1 四柱和宫位

固定宫位是默认语义，不直接等同于事件结论：

```text
年柱：祖上、早年、外部环境、远方
月柱：父母、同辈、社会平台、工作环境
日柱：命主身体、夫妻宫、主位
时柱：子女、晚景、结果、远期事项
```

性别和问题类型必须参与象义映射。财星在男命婚姻问题中可映射配偶，在事业
问题中优先映射现金流和资源；官杀在女命婚姻问题中优先映射配偶，在事业问题
中优先映射职位、制度和压力。

### 3.2 天干、藏干和力量层级

```text
Occurrence {
    stem;
    position;
    branch_position;
    ten_god;
    visibility;           // 透干、藏干
    hidden_level;         // 本气、中气、余气、无
    rooted;
    season_factor;
    effective_power;
    kong_wang;
}
```

透干、地支本气、月令本气、通根和岁运引动的优先级高于普通余气；不得把透出
的财星与一处余气财星按同等证据处理。

四、宾主与体用
--------------

### 4.1 宾主

通行盲派口径为“年月为宾、日时为主”：日干是命主立极点，日支为身体、家庭和
夫妻宫，时柱为子女、成果、晚景和最终兑现的我宫。若采用其他传承的宾主划分，
必须在报告中明确标注规则来源，不得静默改写。

```text
PalaceRole {
    position;
    fixed_palace;
    role;                  // 主位、宾位、主宾交界
    reason;
    confidence;
}
```

财官位于主位只能表示“与我关系近、具有占有或承接倾向”，不能直接推出一定
得到；仍需验证透藏、根气、合冲、墓库和做功结果。

### 4.2 体、辅助体和目标用

```text
体：日干、日支、时柱及其可调用的禄、印、比劫、食神等主位资源。
辅助体：虽在宾位但能被命主调用的印、比劫、食伤。
目标用：财、官、杀、伤官以及被命主控制、取得或改变的对象。
```

同一字可以有多个标签，但必须注明上下文。例如食神既可能是辅助体，也可能是
制杀的做功源；伤官既可能是目标用，也可能是破坏官星的风险源。

五、关系检测和做功链
--------------------

六合、六冲、三合、三会、半合、拱局、刑、穿、害、破、天干五合、天干生克、
通根、得禄、墓库等统一调用 GanZhi 基础模块。盲派分析层只解释关系，不重新
实现 `is_san_he`、六合或刑冲表。

地支不能仅凭所属五行直接记一条“地支相克”；必须定位到本气、中气、余气或
藏干之间的具体作用。

```text
WorkChain {
    source;
    target;
    source_position;
    target_position;
    source_ten_god;
    target_ten_god;
    direction;              // 主→宾、宾→主、主位内部、宾位内部
    relation;               // 制、化、合、冲、刑、穿、生、墓等
    efficiency;             // 高、中、低
    effective_power;
    result_type;            // 得财、得官、受制、破财、伤身、婚姻变动等
    effective;
    evidence;
}
```

做功方式至少包括制用、合用、化用、生用、墓用和反向做功。合必须区分得到、
合住、合绊、被合走；墓必须区分收藏和制忌。

六、功神、废神和层次
--------------------

功神是参与至少一条有效做功链且产生可解释结果的字或组合。废神是没有有效做功，
或虽参与关系但被合绊、空亡、力量不足而不能产生结果的字或组合。

废神不能按“数量大于 4”直接判定能量分散，应综合数量、有效力量、是否占主位、
是否破坏主做功链及是否被岁运引动。

层次使用多维指标，不使用固定总分直接判富贵：

```text
做功强度 = 关系强度 × 有效力量 × 方向系数
做功有效性 = 已完成作用链 / 计划作用链
做功清纯度 = 主导十神或主导路径的一致程度
做功结果 = 财、官、名、技、权、关系、身体等事件类型
风险项 = 破坏主链、反向做功、空亡、墓闭、合绊、刑冲过重
```

七、墓库、空亡和特殊组合
------------------------

本模块采用五行归库口径：木库为未、火库为戌、金库为丑、水库为辰。以本命乙木
为例，未是木库；癸水的墓库为辰，不能把未写成癸水之墓或笼统写成财库。土的
墓库需结合具体传承与所藏对象说明。墓库结果必须同时返回所墓天干、墓支以及
关系类型（冲、刑、合、穿、无）和状态，不能只输出“开库/闭库”一个标签。

```text
TombRelation {
    tomb_branch;
    stored_occurrences;
    stored_ten_gods;
    relation;                    // 冲、刑、合、穿、无
    state;                       // 闭库、开库、破库、入墓、出墓、待用
    palace_role;
    key_source;
    effect;
    evidence;
}
```

墓用成立至少需要墓库存在、有物可墓、墓库与所墓之物发生关联。冲、刑、合、穿
和岁运引动分别记录，不能把“冲开”和“刑开”合并为无方向标签。主位墓库收藏
宾位财官，和宾位墓库控制主位资源，结果方向相反。

空亡必须记录原局空亡、岁运填实、冲空、合空及所在宫位。空亡不等于不存在，
应区分空而待发、填实、冲起、冲实和空中受制。

完整三合/三会、半合、拱局、合冲竞见分别记录。成局需验证参与支齐备、月令和
透干支持、是否被冲破以及是否被空亡削弱。关系同时产生吉、凶作用时采用双通道，
原始压力和救应分别保存，不在总分中互相抹除。

八、应期层级
------------

```text
原局：定义潜在做功结构；
大运：改变十年主题、力量和宫位；
流年：触发具体结构；
流月：缩小事件窗口；
流日：验证应期落点。
```

岁运检测覆盖岁运并临、岁运相战、伏吟、反吟、天克地冲、填实空亡、冲空、
墓库开闭、合冲竞见、交运首年加权和干支本气/中气/余气双象。

同一流年可以有多个来源和多个溢出方向；进入两个以上事件类型时标记“一源多溢”，
并列记录各源头，不能只保留一个总源头。

事件类型至少分为：财务收入受阻、支出与债务、收入机会、事业技术、合同规则、
人际感情、身体伤灾、迁动变更。身体伤灾的原始压力与救应分开，救应不得抵销
“先伤”记录。

九、象法映射
------------

```text
symbol = 干支象 + 十神象 + 宫位象 + 做功结果 + 应期
```

不得根据单个字直接下结论。例如日支被冲只能生成“夫妻宫/身体宫被引动”，还
要结合配偶星、身体所主、冲的来源和救应后，才生成具体断语。

十、分析伪代码
--------------

```text
analyze_mangpai(request):
    chart = request.chart
    validate_birth_context(request.birth_context)
    occurrences = build_occurrences(chart)
    palaces = resolve_dynamic_guest_host(assign_fixed_palaces(chart), occurrences)
    body_use = classify_body_and_targets(occurrences, palaces)
    relations = GanZhi.detect_all_relations(chart)
    relations += detect_hidden_stem_relations(occurrences)
    relations += detect_tomb_and_kong_wang(chart, occurrences)
    work_chains = evaluate_effectiveness(
        build_work_chains(relations, body_use, palaces), occurrences, request.config)
    useful_waste = classify_work_and_waste(work_chains, occurrences)
    structures = identify_structures(work_chains, relations)
    timing = analyze_da_yun_year_month_day(chart, work_chains, request)
    symbols = map_symbols(chart, palaces, work_chains, request.question)
    event_impacts = classify_events(timing, work_chains, symbols)
    evidence = collect_evidence(occurrences, relations, work_chains, timing)
    warnings = collect_review_items(request, evidence)
    return BlindAnalysisResult{schema_version: "1.1", rule_set: request.rule_set,
        input_pillars: chart.pillars, birth_context: request.birth_context,
        occurrences, palaces, body_use, relations, work_chains, useful_waste,
        structures, timing, symbols, event_impacts, warnings, evidence}
```

十一、工程组织约束
------------------

公共契约和流派实现分离，采用 C++ Modules 的 `.cppm + .cpp` 组织：

```text
src/ba_zi/analysis/
├── analysis_contract.cppm/.cpp
├── ziping/
│   └── ...
└── mangpai/
    ├── mangpai_analysis.cppm/.cpp
    ├── mangpai_bing_zhu.cppm/.cpp
    ├── mangpai_zuo_gong.cppm/.cpp
    ├── mangpai_muku.cppm/.cpp
    ├── mangpai_transit.cppm/.cpp
    └── mangpai_presenter.cppm/.cpp
```

统一入口：

```cpp
AnalysisRequest request;
request.method = AnalysisMethod::BlindSchool;
request.birth_context = context;
request.config = config;
auto result = analyze_ba_zi(chart, request);
```

控制器负责流派路由；盲派模块负责盲派规则；GanZhi/BaZiBase 负责基础历法、

十二、验证标准
--------------

最少覆盖：主位/宾位财官、透藏力量、完整三合与半合、墓库开闭、空亡填实和冲空、
制用/合用/化用/生用/墓用、岁运组合、交运首年、多源多溢、救应与原始压力分列，
以及中文输出不泄漏内部枚举值。

本规范的封闭条件不是“所有口诀都已编码”，而是每个已启用规则都有明确适用范围、
输入、输出、证据和回测样例；未确定的传承差异必须标记为待复核。
