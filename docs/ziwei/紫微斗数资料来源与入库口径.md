工作簿的“六十星系专页”逐行保留该 60 个专页的 URL、抓取状态与入库核对清单。该目录与项目现有 69 组守命星系并非一一等同：前者是外部知识库的 60 组专页编排，后者是项目按十四主星视角去重后的组合索引。因此不得把“已抓到专页”写成“69 组规则均已实现”。

2026-09-17 已由公开检索核到[天府丑未](https://mingming3.com/cn/ziwei/articles/sixty-chart-format/tianfu_chouwei)、[天府卯酉](https://mingming3.com/cn/ziwei/articles/sixty-chart-format/tianfu_maoyou)与[天府巳亥](https://mingming3.com/cn/ziwei/articles/sixty-chart-format/tianfu_sihai)三份明明观止专页；它们可作为“天府独坐地支—对宫—财帛—官禄—生年分支”的待校条件来源。对“紫微天府寅申”执行同站精确检索后，尚未返回可直接对应的专页，故仍标为待复取，不能以目录、相近天府独坐页或猜测 URL 替代该组合的规则来源。

专页资料只记录来源定位与条件化摘要，不复制原文长篇断语；实际入库必须转写为本项目自己的条件、规则标识、成立／减力／未成立理由与中文展示文案。

## 3. 方法与流派口径

资料表的“流派与推演层”将三合、飞星、自化、生年四化、宫干四化、亮度与限运分开记录。三合用于同宫与三方四正的结构审看；飞星记录宫干四化由何宫飞向何宫的有向关系；自化是本宫化象的细项。三者可以在报告中并列，却不能共用一个没有来源、方向与版本的分数或结论。

四化表应明确版本：当前公开资料所列的《全集》表，与《全书》在庚、壬两干化科存在差异。每条四化结果至少保留 `version`、来源层（生年／大限／流年／宫干）、化曜、来源宫和落点宫；不得让后起的限年飞化覆盖本命四化。

工作簿“**四化版本与实现对照**”逐干、逐化象保存项目完整星名表、十四主星强类型投影、iztro 原文表的自标口径，以及明明资料页列出的《全集》表和其明确提示的《全书》差异。当前项目 `get_si_hua_star_names` 的完整表含文昌、文曲、左辅、右弼；`get_si_hua_stars` 仅返回 `ZhuXing`，故这些辅曜在后者中留空是类型边界而非漏算。盘面生年四化需以星名 API 对主星、辅星、煞曜、杂曜分别标记，不能把十四主星投影的空位写成“未化”。

“**格局原始标题索引**”已将 [iztro 格局源文档](https://raw.githubusercontent.com/SylarLong/iztro-docs/main/learn/pattern.md)的全部二级标题逐项登记，并与项目 `GeJuType` 枚举及当前实现检出状态比对。表中“已有枚举与实现检出”只表示项目存在对应入口；“未建立同名枚举”表示资料标题仍处于待评估队列。两种状态都不能跳过参与星曜、宫位／三方范围、必要条件、煞忌破格条件与采用口径的拆分。

岁限四化另有“命局—大限—流年—流月—流日—流时”的分层口径；不同资料对大限与流年宫干是否重排并不完全一致。此类差异必须成为 `method` 的显式配置与报告来源说明，不能由分析器暗中选择。[紫微麦的岁限四化资料](https://www.ziwei.my/zi-wei-dou-shu-portfolio/ming-ju-sui-xian-si-hua-guan-xi/)可作为该分层口径的外部索引；飞星的生年四化与宫干飞化分工则另见[飞星资料](https://www.14mainstars.com/14-main-stars/feixing/shengnian-sihua?lang=zh)。

运限还要明确可计算层级与版本开关。[iztro 运限说明](https://docs.iztro.com/posts/horoscope)将大限、小限、流年、流月、流日、流时区分为独立层，并说明小限的流曜／四化处理；这可以作为契约分层的交叉资料，但不是项目默认口径。[iztro 配置说明](https://docs.iztro.com/posts/config-n-plugin)还列出年、限运干支分界、晚子时、安星 `default`／`zhongzhou`、四化与亮度表等开关。项目实现必须把所采用口径显式写入请求、结果和报告，不能让外部默认值覆盖既有回归盘。

身宫只叠入命、夫妻、财帛、迁移、官禄、福德六宫之一，并非第十三宫；报告中应把“身宫叠入何宫”作为宫位关系呈现，而非编造固定年龄切换点。

“十二宫与身宫”保存各宫的本义与排盘结构；“宫位联动资料”另存命财官迁、事业的官迁、姻缘的夫妻福德、财帛的财田与本命—大限—流年的叠宫资料。两表不可合并：前者回答宫位本身是什么，后者回答某一占题至少还要会看哪些宫与哪些时间层；二者都不替代三方四正、四化版本与辅煞条件。

### 4.1 辅星、杂曜与神煞的资料边界

主星不能覆盖辅星和神煞的安置、名称及展示资料。已可访问的 [十四辅星](https://docs.iztro.com/learn/minor-star)、[三十七杂曜](https://docs.iztro.com/learn/adj-star) 与 [四十八神煞](https://docs.iztro.com/learn/dec-star) 被分别登记在工作簿“iztro 文档索引”。其用途是补齐词条目录、安星条件和盘面说明；任何星曜的白话解释都只能作为条件化展示素材，不能盖过主星、四化、同宫和三方四正结构，也不能写成确定应事。

“十四辅星词条与归属”将公开资料的六吉、六煞、二助逐项登记阴阳、五行、斗分和化气，并对照项目 `FuXing`、`ShaXing`、`ZaYao` 枚举。公开资料列为二助的天马在项目中归入 `ZaYao`；此处只记录“资料分类／实现分组”的差异，既不据此改写安星规则，也不将分类标签直接等同吉凶裁断。

本轮已从三十七杂曜公开源文档逐项建立名称与分类索引：交际四曜、孤傲三曜、才艺四曜、矜贵五曜、精神六曜、幸运四曜、健康四曜、封赏三曜和思想四曜。该目录只说明资料页的分类与条目覆盖，项目现有 `ZaYao` 的名称、安置规则及类别若与其不同，必须另做对照表，不可因同名或近义就自动视为同一规则。

四十八神煞也已按长生、博士、将前、岁前四组逐项建立项目枚举对照。四组各有 12 项，当前名称均能在对应项目枚举中定位；这只验证词条覆盖，不验证安置公式、流年起法或解释口径。长生与博士是固定层，将前与岁前是流动层，报告契约必须携带其层次与来源时点。

公开[安星诀](https://docs.iztro.com/learn/setup)第 8 至 44 节已拆成“安星诀规则对照”：从紫微、天府两组主星到辅煞杂曜、长生博士及流年两组神煞均建立了章节、规则输入、项目函数和链接的对应关系。该表的“检出”是代码存在性检查，不能替代公式或边界样例验证；例如确有导入者需见定义的编译期小函数时，定义可合法保留在 `.cppm`，不应因没有 `.cpp` 中的同名定义而误报缺失。

亮度资料同时分为通行七级表与项目的 Metis 扩展表。前者仅含庙、旺、得、利、平、不、陷；项目 `LiangDu::XianYao` 的“闲”必须携带亮度表版本，不可在对照七级资料时改写为“平”。工作簿将此视为版本边界，而非星曜吉凶判定。

工作簿“**十四主星亮度对照**”已逐颗列出寅至丑十二格的公开 iztro 七级表、项目 `BrightnessSchool::Iztro` 表以及 `BrightnessSchool::MetisDefault` 表，并由 `zi_wei_brightness.cpp` 自动读取项目两个主星亮度函数。该表只在“公开七级表／项目 Iztro 表”之间做逐格对照；Metis 表另列其“闲”扩展和其他口径差异，不宣称与七级资料完全等同。

本轮对照当前公开 iztro 资料时，项目 Iztro 表有两格需要回查版本：太阳酉宫为“平”而公开表为“陷”，七杀酉宫为“旺”而公开表为“庙”。它们在确认上游版本前只标为“需复核”，不自动改写现有排盘结果，也不把“公开页面当前内容”误当作唯一历史版本。

## 6. 新资料的入库检查表

新增任一网页、古籍段落或格局资料时，必须答清：

1. 来源是原典、校勘、现代三合、飞星，还是一般讲解？
2. 它描述的是排盘规则、星曜本义、组合关系、格局，还是限运作用？
3. 成立条件是否包含地支、宫位、三方四正、亮度、四化、吉煞或性别/顺逆行？
4. 是否与已有规则版本冲突？冲突时可否并存为不同 `method`？
5. 输出是否保留“成立条件/未成立理由”，而非把该条直接写成确定应事？
